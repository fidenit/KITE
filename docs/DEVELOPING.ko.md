> 이 문서는 0.3.0 기준의 옛 판이다. 지금 맞는 것은 영어판 [DEVELOPING.md](DEVELOPING.md)다. 0.4.0에서 `src/core.rs`·`src/lang.rs`는 `protocol/rust/src/`로 옮겨졌고, 환경 변수 이름은 `APERIT_...`로 바뀌었다(옛 `LYBOARD_...`도 읽는다).

빌드, 키, 부품을 더하는 법, 코드의 구조. 프로그램이 무엇인지는 [README](../README.ko.md)에 있다.

## 빌드해서 실행

Windows:

```powershell
.\run.ps1          # 빌드해서 실행
.\run.ps1 test     # 테스트
.\run.ps1 pack     # 들고 다닐 수 있는 폴더 portable\APERIT 만들기
```

Mac (Rust는 [rustup](https://rustup.rs)으로 설치, Xcode 명령줄 도구 필요):

```sh
./run.sh            # 빌드해서 실행
./run.sh test       # 테스트
./run.sh pack       # portable/APERIT/APERIT.app 만들기
```

Windows 빌드에는 Rust(`stable-x86_64-pc-windows-gnu`)와 MinGW(WinLibs)가 필요하다. 실행 파일 옆에 `WebView2Loader.dll`이 있어야 뜬다(`run.ps1`이 복사한다).

소개 영상(`KITE-promo.mp4`)을 다시 찍고 편집하는 방법과 녹화용 환경 변수는 [`tools/promo/README.md`](../tools/promo/README.md)에 있다.

## 키

키(Claude, Jev, ElevenLabs, 다른 모델, AG-UI 헤더)는 **설정** 창에서 넣는다. 평문 파일로 남지 않고 앱 안에 암호화해서 보관한다: Windows는 이 PC의 이 계정에서만 열리게(`data/keys.bin`), macOS는 로그인 키체인에. 옛 버전이 남긴 `key.txt`·`jev.txt`·`eleven.txt`·`openai.txt`의 키 줄·`agui.txt`의 헤더 줄은 다음 실행 때 옮겨 담고 지운다(`src/secret.rs`).

| 파일 | 내용 | 없으면 |
|---|---|---|
| `voice.txt` | ElevenLabs 목소리 ID | 기본 목소리 |

`data/`, `vault/`는 저장소에 올라가지 않는다.

## 부품 더하기

화면에 놓이는 카드의 종류(부품)는 `src/core.rs`의 `PARTS` 한 곳에 등록되어 있다. 부품 하나에 관한 것(이름, 기본 크기, 받는 필드와 글자 한도, 항목 형식, 무엇에 쓰는지)이 모두 거기 있고, AI에게 주는 부품 표도 이 목록에서 만들어진다. 지시문(`prompt.md`)의 표를 따로 고치지 않는다.

새 부품을 더하려면 세 군데를 고친다.

1. `src/core.rs`의 `Kind`에 종류를 하나 더한다.
2. 같은 파일의 `PARTS`에 등록한다. `purpose`와 필드 설명은 AI가 부품을 고를 때 읽는 글이다.
3. `src/ui.rs`의 `draw_body`에 그리는 법을 더한다 (컴파일러가 빠진 종류를 알려 준다).

항목에 지켜야 할 형식이 있으면 `core.rs`의 `put_item`에 검사를 더한다. 사용자의 답을 받는 부품이면 `Kind::asks`에 넣는다. 그러면 "내 차례" 자리로 온다.

## 안드로이드 앱 (`android/`)

폰에서 쓰는 APERIT. 코드 하나에서 앱 두 개가 나온다 (`android/app/build.gradle.kts`의 `productFlavors`).

| 갈래 | 앱 | 엔진 |
|---|---|---|
| `free` | APERIT (`com.fidenit.kite`) | 사용자가 넣은 Claude API 키로 폰이 Claude API 를 직접 부른다. 고급 선택으로 내 서버의 Claude Code(SSH)도 쓸 수 있다 |
| `pro` | APERIT Pro (`com.fidenit.kite.pro`) | 아무것도 넣지 않는다. 한 턴은 우리 서버의 Claude Code 에서 떼어 돌고 폰은 HTTPS 게이트웨이(아래)로 따라 읽는다. 처음 켤 때 폰이 스스로 등록한다 |

```sh
cd android
./gradlew assembleFreeDebug                                   # app/build/outputs/apk/free/debug/app-free-debug.apk
./gradlew -PaperitGatewayUrl=https://<게이트웨이> assembleProDebug # 주소를 안 주면 에뮬레이터에서 이 PC 의 http://10.0.2.2:8787
android/scripts/check-apk-secrets.sh <apk>                       # apk 에 키·기기 토큰·개인 키·Bearer 토큰이 있으면 exit 1, 들어 있는 URL 호스트를 모두 보인다
./gradlew testFreeDebugUnitTest                               # 보드·수정 언어·API 엔진(가짜 서버로 한 턴)·서버 명령 줄·Jev/ElevenLabs 호출(가짜 서버)·앱 시작과 복원(Robolectric, JVM)
```

JDK 17 이상(Android Studio 의 jbr)과 안드로이드 SDK 가 필요하다. `ANDROID_HOME` 이나 `android/local.properties` 의 `sdk.dir=`로 SDK 자리를 알려 준다.

| 파일 (`app/src/main/java/com/fidenit/kite/`) | 역할 |
|---|---|
| `core/Board.kt`, `core/Lang.kt` | 보드와 화면 수정 언어. `src/core.rs`, `src/lang.rs` 를 옮긴 것 |
| `engine/Api.kt` | Claude API 엔진 (공식 Java SDK). 스트리밍, 도구 반복, 1시간 지시문 캐시, 요청마다 사용량과 어림 비용을 더한다. 흐름은 `src/agent.rs` 와 같다 |
| `engine/PhoneTools.kt` | 폰에서 도는 도구: `screen`, 기억 보관함(`note_*`, 앱 저장소의 `vault/`). 웹 검색·읽기는 Anthropic 서버 쪽 도구 |
| `engine/Jev.kt`, `engine/Decide.kt` | 판단 모델: TypeSafe Jev 호출(`src/jev.rs`)과 턴 앞뒤의 작은 결정(`src/decide.rs`). 질문 글과 기준 숫자는 데스크톱과 같다 |

| `Journal.kt` | 앱이 꺼져도 남는 파일: 돌고 있는 턴, 줄 세워 둔 말·카드 조작 알림, 서버에서 아직 치우지 못한 실행, 지금 보는 주제 |

| `ui/` | 화면: 주제, 카드, 설정 |

- **서버의 턴은 떼어 돈다.** 앱은 턴 글을 서버의 `~/.kite/runs/<id>.in` 에 올리고 `setsid nohup` 으로 `claude` 를 그 자리에서 시작한다. 출력은 `<id>.out`, 끝난 코드는 `<id>.exit`, 감싼 bash 의 번호는 `<id>.pid` (`<id>` 는 앱이 만든다: `[A-Za-z0-9-]+`, 셸에 넣기 전에 검사). 앱은 SSH 로 `.out` 을 아직 받지 못한 줄부터 따라 읽는다 (서버가 줄마다 `>` 를 앞에 붙이고, 앱은 줄바꿈으로 끝난 줄만 센다). 연결이 끊기거나 40초 동안 아무것도 오지 않으면 1·2·4·8·15·30초(그 뒤 30초) 간격으로 다시 붙어 받은 줄 다음부터 이어 읽고, 상태 줄에 그렇다고 보인다. 한 실행의 끝은 끝났다는 줄뿐이고 첫 `result` 가 아니다 (`claude` 한 개가 `result` 를 두 번 낼 수 있다). 멈춤 명령은 신호를 보내지 않는다: 멈춤 요청 파일 `<id>.stop` 을 남기고, 남겼다는 한 줄을 낸 뒤 (앱은 이 줄부터 멈춤이 닿은 것으로 본다. 실행이 끝나는 데 더 걸려도 그렇다) 끝난 코드가 적히기를 3초쯤 기다린다. 감싼 bash 는 자기가 띄운 `claude` 의 번호를 셸 변수로만 갖고 있다가 그 자식이 살아 있는 동안 0.2초마다 그 파일을 본다 (살아 있는지는 bash 가 스스로 아는 것으로 본다. `ps` 는, `ps` 가 답하지 않으면 `/proc` 은, 그 자식이 아직 자기 자식이고 좀비가 아닌지 더 볼 뿐이어서 `ps` 가 실패하거나 옵션을 몰라도 지켜보기는 끝나지 않는다). 신호는 그 자식이 살아 있고 자기 자식인 것을 방금 확인한 차례에만, 그리고 멈춤 요청 파일이 아직 있을 때만 보낸다: 그런 첫 차례에 그 자식과 자손에 TERM (자손부터), 그 뒤 1초쯤(그런 차례 다섯 번) 지나면 그 나무에 KILL 을, 자식이 없어질 때까지 그런 차례마다 보낸다. 확인하지 못한 차례(`ps` 도 `/proc` 도 답하지 않았다)에는 아무 신호도 보내지 않고 계속 지켜본다. 자식이 없어지면 자기 세션에 남은 것도 끝내고 (`setsid` 가 있는 서버에서만) 끝난 코드를 적는다. 신호를 받는 번호는 자기 자식이거나 프로세스 목록이 방금 준 것뿐이고, 숫자이고 1보다 크고 자기 번호가 아닌지 확인한 뒤에 쓴다. `.pid` 의 번호는 감싼 bash 가 아직 있는지 볼 때만 읽으므로 (명령 글로 확인, 신호 없이) 낡았거나 틀린 pid 파일 때문에 다른 프로세스에 신호가 가는 일은 없다. 따라 읽기는 그 검사가 0.3초 간격으로 세 번 잇달아 감싼 bash 를 찾지 못하고 끝난 코드도 없을 때만 그 실행을 `lost` 라고 한다. `claude` 가 살아 있는데 감싼 bash 가 밖에서 죽으면 멈춤 요청을 볼 것이 없다: 그 `claude` 는 스스로 끝날 때까지 돌고 멈춤으로 끝낼 수 없다. 멈춤 요청 뒤에 닿은 시작은 아무것도 띄우지 않고 `stopped` 를 적는다. 실행을 치울 때는 턴 글 `.in` 을 맨 먼저 지우고 (늦게 닿은 시작이 띄울 것이 없게), 그 실행이 아직 돌 수 있으면 멈춤 요청을 남기거나 새로 적는다: `.pid` 파일이 있고 `.exit` 의 끝난 값이 없거나 비었거나 `stopped` 일 때다. 아니면 (`.exit` 에 진짜 끝난 코드가 있거나 `.pid` 파일이 없다) 멈춤 요청도 지운다. 남긴 `.stop` 파일은 `.exit` 옆에 이레 뒤 정리 때까지 남는다. 서버가 실행이 끝났다고 답하면 (끝난 코드·`stopped`·`lost`·`gone`) 앱은 그 결과를 한 번만 넘기고, 다시 붙거나 그 실행을 다시 시작하지 않는다. 10초쯤 안에 서버에 알리지 못하면 (연결하는 중·다시 붙는 중에도: 연결 끊기는 진행 중인 연결을 기다리지 않는다) 턴은 화면에서 끝나고, 오류 줄에 멈춤이 서버에 닿지 않았다고 알리며, 앱이 자기 연결로 서버에 닿는 대로 그 실행을 멈추고 치운다 (1·2·4·8·15·30초 간격, 앱을 켜거나 앞으로 돌아오면 바로. 다음 턴까지 기다리지 않는다). 멈춘 뒤에는 아무것도 저절로 시작하지 않는다: 줄 세운 말은 버리고, 카드 조작 알림은 다음에 보내는 말과 함께 간다. 끝난 실행의 서버 파일(`.in .out .err .pid`)은 저장한 보드와 대화가 디스크에 닿고, 그다음 기록 지우기가 디스크에 닿은 뒤에야 지운다 (쓰기가 실패하거나 5초를 넘기면 기록과 서버 파일을 그대로 두고, 다음에 켤 때 그 턴을 다시 받는다). 멈춤이 닿지 않은 실행의 파일은 멈추기 전에는 지우지 않는다. `.exit` 는 남겨 두고(이레 뒤 턴을 올릴 때 지워진다), 이미 끝난 실행에 다시 붙으면 `gone` 이 나와 같은 말이 두 번 돌지 않는다. 멈추거나 치우지 못한 실행 번호는 `toclean.json` 에 합쳐 적고(덮어쓰지 않는다), 서버에서 멈추고 치운 것이 확인된 뒤에야 목록에서 뺀다.
- **앱이 다시 켜져도 남는 것.** SSH 턴은 첫 네트워크 호출 전에 `inflight.json`(턴 글, 사용자가 본 말, 턴 시작 전 보드, 실행 번호, 서버(계정@주소:포트), 시작이 확인됐는지)을 쓰고, 실행 번호가 적힌 기록이 디스크에 닿은 뒤에야 서버에 올린다. 기록은 그 턴을 시작한 서버에서만 이어 받는다: 설정이 다른 서버면(어느 서버인지 없는 옛 기록도) 거기서는 이어 받지도 다시 시작하지도 않고, 저장된 화면을 보여 주고 한 줄로 알린 뒤 기록을 지운다. 서버에 그 실행이 없을 때 다시 시작하는 것은 기록에 시작된 적이 없다고 적혀 있을 때뿐이다. 앱이 꺼지기 전에 멈춘 턴은 다시 이어 받지 않는다. 앱이 켜질 때 이 파일이 있으면 턴 시작 전 보드로 되돌리고, 그 뒤에 만진 카드를 다시 반영한 다음 0번 줄부터 그 실행을 따라 읽어 결과를 보드에 반영한다 (따라잡는 동안 소리는 내지 않는다). 턴을 처리하고 저장한 뒤 파일을 지운다. API 엔진(과 실행 번호를 받기 전에 끊긴 SSH 턴)은 파일이 있으면 "마지막 말이 끊겼다"고 한 번 알리고 그 말을 보여 줘서 다시 보낼 수 있게 한다. 줄 세워 둔 말과 카드 조작 알림(`queue.json`), 서버에서 아직 못 치운 실행, 지금 보는 주제, 마지막 한마디도 되살아난다. 보드는 카드를 만질 때마다 쓰기 일꾼 하나가 쓰기와 지우기를 줄 선 순서 그대로 하고(저장 공간이 꽉 차는 등으로 실패한 쓰기는 앱이 디스크를 기다릴 때마다 일꾼이 다시 해 보므로, 디스크가 다시 되면 앱을 다시 켜지 않아도 저장이 된다), 앱이 뒤로 갈 때와 화면이 닫힐 때 다 쓸 때까지 (1초까지만. 메인 스레드가 일꾼을 기다리는 곳은 여기뿐이다) 기다리므로 앱이 정상적으로 멈추기 전에는 디스크에 있다. 말로 대화하기는 그때 꺼진다. 턴을 저장한 뒤 기록을 지우기 전에 꺼졌다면 다시 붙을 때 그 턴의 말만 차례 번호(기록과 `recent.json` 의 말마다 적어 둔다)로 가려 빼므로 40개까지만 저장해도 그 전의 말은 빠지지 않고(번호가 없는 옛 기록이면 빼지 않는다), 끊긴 동안과 다시 받는 동안 만진 카드는 따라잡은 뒤에 순서대로 반영한다. 설정의 연결 시험은 자기 연결을 써서 돌고 있는 턴을 건드리지 않는다.
- 아직 없는 것: 포그라운드 서비스·알림(결과를 받으려면 앱을 열어야 한다), API 엔진 턴 이어 받기, 실제 폰에서의 확인 (엔진은 실제 `sshd`·`claude` 서버로, 앱 쪽은 JVM 시험과 코드 읽기로 확인했다).
- 지시문은 데스크톱과 같은 `src/prompt.md` 를 빌드할 때 복사해 쓰고, 폰에 맞는 덧붙임(`PHONE_NOTE`, `NOTE`)을 뒤에 붙인다. 부품 표는 `core/Board.kt` 의 `PARTS` 에서 만든다: `src/core.rs` 의 `PARTS` 를 고치면 여기도 같이 고친다 (`partsMatchDesktop` 시험이 어긋남을 잡는다).
- API 엔진의 핵심 기억은 `vault/기억/핵심.md` 이고, 데스크톱처럼 따로 정리해 주는 모델이 없어서 모델이 `note_append` 로 직접 적는다.
- 개발용 빌드만 `10.0.2.2`·`localhost` 로의 암호화 없는 연결을 허용한다 (`src/debug/res/xml/network_security_config.xml`).
- **판단 모델(Jev).** 설정에 TypeSafe Jev 키를 넣으면(다른 키처럼 암호화 저장소에 둔다. 비어 있으면 없는 것) 한 턴에 작은 결정 두 가지가 붙는다. 둘 다 `https://api.typesafe.ai/v1/systemone` 한 번 호출이고, 2.5초 안에 끝나지 않으면 버린다 (키 없음, 답 없음, 200이 아닌 상태, 모양이 다른 본문은 모두 "결정 없음": 턴은 Jev 없이 돌던 그대로 가고 화면에는 아무것도 띄우지 않는다).
  - 턴 앞(앱이 다시 켜져 다시 붙는 턴에는 하지 않고, 입력이 있을 때만): 요청의 종류를 상태 줄에, Jev가 고른 주제를 바로 보여 주고, 일·화면 수정·기억 찾기를 시킨 말이면 받았다는 한마디를 먼저 건넨다("네, 바로 해볼게요." 등. 말로 대화 중이면 소리 내어 읽고, 아니면 카드 아래 한마디로 보인다). 턴 글에는 `<already_said>` 가 붙어 모델이 같은 인사를 되풀이하지 않는다. 깊이·종류는 확신 0.5 이상, 주제는 0.6 이상일 때만 따른다.
  - 턴 뒤(뒤에서): 모델이 건드린 카드(최대 20장)마다 화면만 보고 분명한지, 얼마나 중요한지를 묻는다. 분명할 확률이 0.4보다 낮은 카드는 다음 턴 글의 `<review>` 에 한 번 실리고, 중요도(점수/2, 세 단계)는 답을 기다리는 카드 다음에 중요한 카드가 먼저 오도록 순서에 쓰인다.
  - 부를 때마다 앱 파일의 `jev.log` 에 남는다 (시각, 앱 버전, 입력 앞 40자, 고른 값, 걸린 시간. 키는 적지 않는다).
- ElevenLabs: 목소리로 읽기가 그 문장의 소리가 나가기 전에 실패하면 스피커를 멈추고 그 문장을 폰의 기본 음성으로 읽는다. 문장을 읽는 도중에 끊기면 스피커를 멈추고 그 문장은 다시 읽지 않는다. 화면에는 한 줄로 무엇이 문제인지(키 거절, 사용 한도, 연결, 폰이 소리를 틀지 못함, 그 밖: `Eleven.Why`), 그 문장을 어떻게 했는지, 할 일을 일상어로 알린다(`voice/Speaking.kt`). 이 줄은 문장을 실패 없이 읽을 때까지 한 번만 띄운다(폰의 기본 음성을 쓸 수 없을 때도). 받아쓰기는 HTTP 401·403·429면 바로 끝낸다. 받아쓰기가 실패하면 같은 꼴의 한 줄(`Speaking.heardNotice`: 까닭, 그 말은 보내지 않았고 계속 듣는다는 것, 할 일)을 다시 받아쓸 때까지 한 번만 띄운다(그사이 말로 대화하기가 꺼졌으면 "계속 듣고 있습니다" 대신 꺼져 있다고 쓴다). 폰의 기본 음성은 한도(엔진이 켜지기까지 10초, 문장 하나에 5초 + 글자마다 1초: `Speaking.phone`)를 넘기면 그 문장을 읽지 못한 것으로 치고 넘어간다. 마이크를 쓸 수 없으면 말로 대화하기를 끄고 같은 꼴의 한 줄(`Speaking.micNotice`: 권한 없음, 열지 못함, 듣는 중에 멈춤)을 띄운다. ElevenLabs 키가 비어 있으면 마이크 권한을 묻지 않고 키 오류를 띄운다.
- 아직 없는 것(Jev): 기억 노트 미리 읽기(SSH 엔진의 노트는 서버에 있다), 겹치는 주제를 합치는 정리 턴(폰에는 쉬는 동안 도는 턴이 없다), 옛 대화 찾기(`<recall>`, 폰에는 턴 기록이 없다), 기다리는 중 들린 말이 비서를 부르는 말인지 판단(Jev가 아니라 Claude Haiku), Jev가 정하는 턴별 생각의 깊이(설정의 깊이를 쓴다).
- 아직 없는 것(음성): 오디오 포커스(전화·음악과 겹칠 때), 폰이 스피커 소리를 자기 말로 듣는지, 마이크를 끝낼 때 화면이 0.5초까지 멈추는 것. 실제 기기에서만 드러난다.
- 확인하지 못한 것: Jev와 ElevenLabs 경로는 가짜 서버로만 돌려 봤다(api.typesafe.ai·api.elevenlabs.io 에는 부르지 않았다). 실제 폰도 에뮬레이터도 쓰지 않았고, 뷰모델은 JVM 에서 Robolectric 으로 돌렸다.
- 아직 없는 것: 경로 찾기, 작업자, 브라우저 도구, 문자·전화, 붙인 사진, Pro 의 Play 구독 연결.

## 게이트웨이 (APERIT Pro)

APERIT Pro 는 별도 비공개 저장소의 게이트웨이에 붙는다. 게이트웨이는 한 턴을 서버의 Claude Code 로 떼어 돌리고(SSH 엔진과 같은 방식), 보드를 서버에도 둔다. 주소는 빌드할 때 넣는다 (`-PaperitGatewayUrl=https://…`, `BuildConfig.GATEWAY_URL`. 저장소에는 적지 않는다). 앱 쪽 약속:

- **이름표.** 처음 켤 때 기기 번호(UUID)와 비밀 글(`apd_` + 무작위 32바이트, base64url)을 만들어 암호화 저장소에만 둔다. 그 저장소를 열거나 읽지 못하면(다른 폰에 복원, 손상) 지우고 새 기기로 다시 등록한다 (일반 저장소로 내려가지 않는다). `POST /v1/enroll` 은 번호와 비밀 글의 SHA-256 을 보내고, 답은 `approved`, 6자리 번호가 붙은 `pending`(서버에서 대표가 허용), `revoked`. 빌드에 한 번만 쓰는 등록 표를 넣을 수 있다 (`-PaperitEnrollTicket=…`, `BuildConfig.ENROLL_TICKET`, 저장소에 두지 않는다): 서버가 판단할 때까지만 보내고, 이미 쓰였거나 기한이 지난 표면 폰은 번호로 허용을 기다린다. 허용 대기는 서버에서 30분 뒤 사라지고, 그러면 `/v1/me` 가 401 을 주어 앱이 다시 등록하고 새 번호를 보인다. 상태는 앱이 켜질 때, 앞으로 돌아올 때, 말을 보내기 전에 묻는다.
- **턴.** `engine/Link.kt` 가 `ClaudeCode` 아래의 이음매다: `SshLink` 는 지금까지의 명령을 SSH 로 보내고, `GatewayLink`(OkHttp)는 `PUT /v1/runs/{id}/input`, `POST …/start`, `GET …/follow?n=`(server-sent events: `data:` 하나가 SSH 따라 읽기의 한 줄), `POST …/stop`, `DELETE /v1/runs/{id}`, `GET …/err`, `PUT /v1/system`, `GET /v1/core`, `GET /v1/info` 를 쓴다. 끊긴 호출은 끊긴 SSH 명령과 같이 "n번 줄부터 다시 붙기"가 되고, HTTP 401·403 은 이유를 적은 한 줄로 턴을 끝낸다. `APERITFAIL busy`(서버가 이미 한도만큼 턴을 돌리거나 메모리가 모자람)는 따로 한 줄. 모든 요청에 `Authorization: Bearer <비밀 글>` 과 `X-Aperit-App: <판>-pro` 가 붙는다.
- **상태.** 폰에 저장할 때마다 보드·저장하는 40개의 말·보던 주제를 조금 뒤에 `PUT /v1/state` 로 올린다 (모아서, 다시 해 보며, 화면을 막지 않는다. `If-Match` 는 폰이 가진 마지막 판). 켤 때 폰에 저장된 보드가 없거나 폰의 판이 오래됐으면 서버 것을 쓰고, 412 면 서버 것을 쓰고 한 줄로 알린다. 바뀌기 전 폰의 것은 `state-backup.json` 에 남긴다.
- 앱 파일의 `pro.log` 에 상태 변화와 상태 판 번호·크기를 남긴다 (비밀 글·등록 표·내용은 적지 않는다).
- **음성 (0.3.0).** `voice/Eleven.kt` 는 `Target`(주소 뿌리 + 인증 머리글)으로 부른다: 무료 앱은 전과 같이 ElevenLabs(`https://api.elevenlabs.io/v1/…`, `xi-api-key`), Pro 는 `<게이트웨이>/v1/voice/text-to-speech/{voice}/stream?output_format=…` 와 `<게이트웨이>/v1/voice/speech-to-text` 를 기기의 Bearer 와 `X-Aperit-App` 으로 (키 머리글 없음, 넘겨주기 따르지 않음, 보내는 본문은 같다). `/v1/me` 가 `"voice": true|false` 를 주면 앱은 마지막 값을 두고(상태와 같은 때에 새로 받는다) 참일 때만 대화·마이크 버튼과 설정의 음성 칸(대화 언어, 마이크 민감도)을 보인다. 게이트웨이의 오류 본문(`voice_off`, `voice_key`, `voice_limit`, `voice_refused`, `voice_unreachable`, `rate_limited`, `too_large`, `bad_request`, 기기 문제 401·403)은 `Eleven.Gate` 가 되고, 화면 줄은 `voice/ProVoice.kt` 에 있으며 키나 설정을 말하지 않는다. 401·403 은 보통의 상태 확인을 시작한다. `pro.log` 에는 목소리 호출마다 번호와 낱말만 한 줄 (글자 수, 바이트, 밀리초, 까닭).
- Pro 에서 Jev 는 아직 꺼져 있다. 설정에는 연결 상태와 짧은 기기 번호(앞 8글자), 서버의 목소리가 켜져 있으면 음성 칸이 있다.
- Pro 앱은 클라우드 백업과 기기 간 옮기기에서 빠진다 (`allowBackup="false"`, `src/pro/` 의 `dataExtractionRules`).
